# Восстановленный протокол PCU20Net

Источник — `PCU20Net.Siemens` (форматы) и `PCU20Net.S810Server.Client_DataReceived` (поведение) из предоставленного PCU20Net.exe. Это описание конкретной реализации, а не официальная спецификация Siemens. Команды, объявленные в enum, но отсутствующие в обработчике, не считаются поддержанными.

## Соединение и заголовок

Сервер слушает TCP 6743–6757. Нет баннера, FTP-команд, пассивного/активного соединения данных, SMB-пакетов или TLS. На каждом TCP-соединении сначала Login, затем операция; для каталогов и файлов нужны несколько запросов в одном соединении. Состояния каталогов и открытых файлов принадлежат соединению, а не IP или глобальному handle.

Все числа little-endian. Заголовок запроса и ответа имеет длину 10 байт:

| Смещение | Размер | Запрос | Ответ |
|---|---:|---|---|
| 0 | 2 | Полная длина телеграммы | Полная длина телеграммы |
| 2 | 4 | uiBlockNumber | uiBlockNumber |
| 6 | 2 | usHandle | usHandle |
| 8 | 2 | usCommand | usErrorCode |
| 10 | переменный | Данные команды | Данные результата |

В заголовке ответа **нет номера команды**. Handle копируется из запроса, но не выдаётся сервером как файловый дескриптор. Длина включает сам заголовок; максимум — 65535, полезные данные — 65525. TCP не сохраняет границы телеграмм: новый сервер читает указанную длину, поддерживая разделение и склейку пакетов. Оригинальный обработчик не умеет надёжно разбирать склеенные телеграммы.

Строки: CP1252, завершающий NUL, дополнение нулями до размера поля. В таблице ниже смещения считаются от начала полной телеграммы.

## Команды, реализованные в демоне

| Код | Название | Запрос после заголовка | Ответ и завершение |
|---:|---|---|---|
| 0 | GetVersion | нет | 20 байт версии `V06.02.56`, затем закрытие TCP |
| 1 | Login | см. ниже, полный размер 350 | заголовок, block=1, error=0; TCP остаётся открыт |
| 2 | WriteFileToServer | байты файла с offset=10 | заголовок, block из запроса |
| 3 | ReadFileFromServer | uint32 count, полный размер 14 | заголовок + до count байт; EOF = ответ без данных |
| 4 | ReadDirFromServer | первая телеграмма: path[260] + uint32 attrib; следующие — только заголовок | одна запись за запрос; конец error=120; заключительный запрос block=65535 получает error=0 и закрывает TCP |
| 5 | TerminateConnect | нет | заголовок, block из запроса, закрытие TCP |
| 6 | CloseFile | нет | заголовок, block=65535; закрытие файла и TCP |
| 7 | AccessFile | path[260] + uint32 flags | int32 result: 0 существует, -1 отсутствует; закрытие TCP |
| 8 | MkDir | path[260] | int32 result: 0 успех, -1 ошибка; закрытие TCP |
| 9 | Rename | from[260], to[260] | заголовок, затем закрытие TCP |
| 10 | GetFreeMem | оригинальный обработчик игнорирует тело | int32 -1; закрытие TCP |
| 11 | GetVersionEx | нет | version[20] + uint32 0x62000001; закрытие TCP |
| 12 | OpenFileOnServer | path[260] + uint32 attrib1 + uint32 attrib2; полный размер 278 | заголовок, block=1; при ошибке block=65535, error=40 |
| 13 | ReadLinesFromFileFromServer | поля по 4 байта: numberOfLines на 10, bufferSize на 14 | см. особенности ниже |
| 14 | GotoLine | поля по 4 байта: line на 10, column на 14 | заголовок, block=65535, error=0 либо 141 |
| 22 | LastTelegram | нет | при открытом файле block=255, error=0; иначе block=1, error=11; закрытие TCP |
| 30 | Remove | path[260] | int32 result: 0 успех, -1 ошибка; закрытие TCP |
| 31 | RmDir | path[260] | int32 result: 0 успех, -1 ошибка; закрытие TCP |

Остальные команды получают заголовок block=1, error=11, после чего соединение закрывается. В частности, оригинал объявляет, но не реализует OpenFileOnServer2=23, GetDirList=32, StatFile=33, GetProcessInfo=34, ChModFile=37. GetLinePos=15, NumberOfLines=16, Search=17, WriteBlockLines=19, Replace=20, NumberFile=21 также не реализованы в исследованном обработчике.

## Login

| Смещение | Размер | Поле |
|---|---:|---|
| 10 | 256 | pszIp — строка адреса/имени |
| 266 | 4 | uiUnknown, uint32, назначение не установлено |
| 270 | 40 | username |
| 310 | 40 | password |

Оригинал требует команду 1 и размер 350, разбирает поля, но **не сверяет пароль**. Новый демон проверяет его в `auth=credentials`; `auth=compatibility` воспроизводит принятие любых реквизитов. Без Login оригинал возвращает error=10 даже для версии. LoginEx объявлен как класс, но не используется обработчиком; новый демон его не принимает.

## Файловый обмен

Пример загрузки файла на сервер:

1. TCP connect → Login → ACK(block=1).
2. OpenFileOnServer(`\\SERVER\NC\PART.MPF`) → ACK(block=1).
3. Один или несколько WriteFileToServer с данными → ACK с блоком из запроса.
4. LastTelegram → ACK(block=255) → TCP close. Вместо LastTelegram можно CloseFile → ACK(block=65535).

Чтение: после OpenFile отправлять ReadFileFromServer(count); данные возвращаются без отдельного поля фактической длины — она равна длине телеграммы минус 10. EOF — ответ длиной 10 байт с error=0 и тем же блоком. После EOF файл остаётся открыт до команды закрытия или разрыва TCP.

Оригинал открывает файл через FileMode.OpenOrCreate, игнорируя attrib1/attrib2. Это не усечение: запись более короткого файла оставляет старый хвост. Новый демон по умолчанию заменяет файл целиком и атомарно; параметр `truncate_on_write=false` сохраняет старый хвост. Уже принятые блоки не являются подтверждением долговременного сохранения всего файла: фиксация происходит при CloseFile/LastTelegram. При неподтверждённом обрыве старая версия сохраняется.

## Каталог

Первый запрос содержит UNC-путь с маской, например `\\SERVER\NC\*.*`. Оригинал включает все подкаталоги и файлы по маске, игнорирует attrib. Следующие запросы команды 4 длиной 10 возвращают следующие записи. Записи имеют полный размер 307:

| Смещение | Размер | Поле |
|---|---:|---|
| 10 | 4 | Windows FileAttributes: Directory=0x10, Archive=0x20, ReadOnly=0x01 |
| 14 | 4 | время создания |
| 18 | 4 | время доступа |
| 22 | 4 | время изменения |
| 26 | 4 | размер файла, uint32, для папки 0 |
| 30 | 260 | полное имя |
| 290 | 4 | sWinNTHandle; оригинал оставляет 0 |
| 294 | 13 | короткое имя Windows |

Каждая запись имеет block=1. После последней записи следующий обычный запрос получает error=120, block=1. Затем клиент отправляет команду 4 с block=65535, сервер отвечает block=65535, error=0 и закрывает соединение. Error=120 используется оригиналом также при ошибке перечисления — он не различает пустой каталог и часть файловых ошибок.

На FreeBSD времена передаются как Unix seconds. Оригинал вычитает UTC epoch из локального DateTime без нормализации часового пояса; его отображение времени может отличаться на часовой пояс. FreeBSD ctime не является временем создания, используется как приближение. Длинные 8.3-алиасы не синтезируются.

## Построчные операции и выявленные ошибки оригинала

GotoLine нумерует строки с 0, ищет LF, игнорирует столбец. Хотя поля сериализуются как 32-битные, парсер оригинала читает только младшие 16 бит по смещениям 10 и 14; демон повторяет это.

ReadLines выбирает целые строки, помещающиеся в bufferSize, и сохраняет результат в состоянии соединения. На первом запросе возвращает **две** телеграммы: сначала размером 18 байт, block=65535, тело `(requestedLines:int32, 0:int32)`; затем, если есть данные, block=1 и данные строк. Повторный запрос повторяет сохранённый блок данных. Это соответствует фактическому сериализатору, а не названиям полей `iBytesRead`/`iBytesNeed`: оригинал заполняет их, но `ToHex()` их не отправляет. Для не-ASCII строк оригинал дополнительно выполняет спорное преобразование byte→char→CP1252; новый демон сохраняет исходные байты.

Rename в оригинале безусловно сбрасывает error в 0 даже после исключения. Демон возвращает ошибку вместо ложного успеха. RmDir удаляет только пустую папку. Символические ссылки, выход через `..`, абсолютные локальные пути и неоднозначные имена в новом демоне запрещены.

## Наблюдаемые ошибки

| Код | Использование в исследованной программе |
|---:|---|
| 0 | Успех, также EOF при ответе без данных |
| 10 | Нет Login / ошибка записи |
| 11 | Неизвестная или неподдержанная телеграмма |
| 40 | Ошибка открытия файла |
| 120 | Нет следующей записи каталога / ошибка перечисления |
| 141 | Переход к недоступной строке |
| 255 | Объявлена для ошибки Rename, но затем ошибочно обнуляется |

Enum также содержит ErrorGotoLinePosOnServer=130, но обработчик фактически отправляет 141. Это ещё один пример, почему при восстановлении использовались выполняемые ветки и сериализация, а не только названия.
